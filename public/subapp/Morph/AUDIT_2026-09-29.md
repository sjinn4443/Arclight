# Morph logic, UI and clinical-teaching audit

Initial audit followed by approved fixes. The six findings below are addressed by BIO orientation, explicit non-calibrated/Direct-only Rx scope, shared cataract filtering, canvas bounds, contained guide focus and 44px-high controls with accessible selected states. Field buttons remain narrower than 44px to preserve the compact row. Unit tests, optical/UI regressions and the established offline/reset/Cup/direct-file suite pass. The retained Codex tab needed a fresh loopback preview on port 8095 because port 8090 served older content there. Updated build confirmed by selected-state controls; real toolbar verified 360 × 740 after switching away and back. Clinical and physical-device sign-off remain pending.

## Prioritised findings

1. **Clinical teaching: BIO is not a distinct optical mode.** The degree buttons change only `selectedDegree` and the aperture radius. Drawing retains the same upright image and image scale. Direct and BIO labels therefore imply more than the model supplies. Direct views are upright whereas BIO images are inverted and reversed. Either implement the intended optical distinction or explicitly label these as illustrative field sizes rather than BIO simulation. Reference: https://eyewiki.aao.org/Binocular_Indirect_Ophthalmoscopy
2. **Clinical teaching: Rx scaling is applied identically to Direct and BIO.** The factors 0.74/0.88/1/1.14/1.3 do not depend on viewing method. They should not be presented as a general optical model for both methods. Indirect magnification depends on refractive state and lens geometry: https://pmc.ncbi.nlm.nih.gov/articles/PMC9321138/. Keep numerical factors explicitly illustrative unless an optical model is specified.
3. **Mobile cataract differs materially from desktop.** On a touch-enabled 360 × 740 browser, dense cataract returns only `brightness(0.56)` from `buildFundusFilter()`. The desktop path also applies blur, contrast and saturation. Tint and opacity patches remain on mobile, but the guide promises blur and contrast loss without qualifying this difference. Correct or explicitly scope the performance approximation.
4. **Aperture can be clipped off the stage.** Bounds constrain to the oversized image rather than the visible canvas. A pointer at (12,12) produces aperture centre (12,12), radius 38, so much of the circle lies outside the stage. Intersect image bounds with canvas bounds.
5. **Guide focus trap fails at entry.** The guide initially focuses its container. Shift+Tab then reaches `burger-icon` outside the guide because the trap only recognises its first/last child control. Handle the initial container focus and keep background controls out of the dialog's focus path.
6. **Control accessibility:** Field buttons measure 31 × 31px and Rx buttons 31px high. All lack `aria-pressed`, so visual active state is not exposed as selected state. Increase hit areas where feasible without crowding the existing compact arrangement.

## Further observations

- Field degrees use an illustrative radius lookup rather than a calibrated angular model. The guide should not imply accurate angular coverage.
- Child mode is a movement demonstration, not a model of paediatric anatomy. Preserve this distinction.
- Condition images and full-image placement were inspected. Retain author-approved artwork; photographs alone are not independent validation of diagnoses or severity. AMD is a specific macular example, not a representation of every AMD phenotype.
- `applyCondition()` compares a basename with a full relative path, so its same-image fast path never matches. No user-facing failure demonstrated.
- Image loading has no error handler. A missing image has no useful visible recovery message.
- README still contains obsolete white-appbar instructions despite the current black bar.
- Morph deliberately has no MCQs. The Cup rewards exploring all five conditions, not clinical competence. Do not add a quiz just for fleet symmetry.
