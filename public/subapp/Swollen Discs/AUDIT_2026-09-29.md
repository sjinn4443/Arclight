# Swollen Discs audit — 29 September 2026

Review only. No production code or clinical wording changed. Locked development dependencies installed to run existing checks; diagnostic script and evidence added under output.

## Confirmed engineering issues

1. **Old image under new explanation on load failure.** viewer.js changes the condition/explanation before the replacement image loads. draw() returns before clearing when image dimensions are unavailable and onerror has no usable fallback or visible error. Blocking the suspicious image left the old normal image visible with the suspicious explanation. Clear or mark the pending view and provide a retry/error state.
2. **Timed exposure starts before image readiness.** timed-test.js calls setImageSource then immediately starts its countdown. With a 3.5-second image delay, the timer read 7 while the requested swollen image had not replaced the normal frame. Await decode/readiness before starting exposure; failed images must not count as recognition attempts.
3. **Denied localStorage breaks startup.** hasLocalStorage reads window.localStorage outside the guarded try blocks. A throwing storage getter produced SecurityError and the Swollen button could not change the initial Normal state. Storage unavailability should disable persistence, not the simulator.
4. **Mobile cataract rendering is materially different.** At 360 x 740 dense cataract uses only brightness(0.56) on the retinal image, dropping the configured blur, contrast and saturation filters. Separate occlusion/tint layers remain, so this is not a total loss of the cataract effect. Review perceptual parity with the desktop simulation before changing the performance shortcut.

## Teaching and clinical review

- Initial Normal is a selected teaching example, not an unrecorded patient assessment: preserve it.
- The main card's unqualified Referral / No urgent referral can look like a patient disposition, especially after a deliberately poor view. Clarify that the action belongs to the example. The guide disclaimer is useful but hidden until opened.
- The guide's haemorrhage/hidden-vessel shortcut needs qualification: opacity can hide vessels and haemorrhage alone does not define disc oedema severity. Do not change local urgency intervals automatically.
- Modified Frisen grade definitions largely match the 2010 primary-source table. Grades 1/2 represent real oedema, not merely an absence of definite disease. The app's three examples should not be presented as a full diagnostic or grading scheme.
- MCQ mechanics are sound in the tested paths. Thirty questions are split 10/10/10, with 4/5/7 per attempt and pass marks 3/4, 4/5 and 6/7. Several Advanced questions repeat lower-tier grade recall: q21/q03, q22/q04, q23/q11 and q24/q12. Improve tier depth with clinical uncertainty and serial-comparison scenarios instead of increasing option count alone. IDs are stable but not app-scoped and source-review status is not a separate independent sign-off field.
- Timed practice uses only three source images, transformed repeatedly. Four-round sets do not guarantee all three classes. This is reasonable familiarisation but weak evidence of general recognition skill. Vertical-only flipping is deliberately guaranteed at least once per set; it is artificial augmentation, not normal direct-ophthalmoscope orientation. Label or review that choice rather than silently treating it as a new clinical presentation.
